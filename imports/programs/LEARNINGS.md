## Modelling
- **Progression rules have no home.** "Add 2.5 kg when you get 5×5", "deload 10% after 3 fails", "TM +2.5 kg if the 1+ set hits 2–3 reps", "8+ on the AMRAP doubles the jump", "add a rep per set until 3×8 then move up a progression" all sit in free-text `note`. Propose `progression` on a block (or on the exercise step): `{ "on": "allSetsComplete" | "amrapReps" | "topOfRange", "add": 2.5, "unit": "kg", "thresholds": [{"minReps": 10, "add": 5}], "deload": {"afterFails": 3, "pct": 10} }`. That is enough to drive the "next session" weight for every program here.
- **Percentage loads.** `target` is absolute kg; 5/3/1, nSuns and Ivysaur's "8-rep weight = 90% of 4-rep weight" all need a load relative to a per-lift number the user owns. Propose `loadPct` + `loadRef: "tm" | "1rm" | "bodyweight" | "<stepId>"` on ExerciseStep, and a per-user training-max store keyed by exercise. Until then the `% TM` string in `note` is the only carrier (36 files, ~250 steps use it).
- **AMRAP sets.** `forValue` must be a number, so "5+" is `forValue: 5` with an AMRAP note in a separate `repeat: 1` block. The score (reps achieved) is what drives progression; there is nowhere to record it. Propose `forMode: "amrap"` (min reps in `forValue`, log actual) — same gap crossfit-girls flagged as `forMode: "max"`.
- **Rep ranges (8–12, 3–5).** Modelled at the top of the range with the range in `note`; set ranges (3–4) at the lower number. Propose `forValueMin`/`forValueMax` or `forRange: [8, 12]`.
- **Sets as blocks.** 5×5 = block `repeat: 5` with [exercise, rest], so a 7-exercise PHUL day is 7 blocks with 7 rest steps that say the same thing; nSuns days with 9 distinct-percentage sets become one block with 18 steps. A `sets: [{reps, pct, amrap}]` array on an exercise step would flatten most of this.
- **Alternation across sessions.** Starting Strength alternates press/bench every session independently of the A/B day; Metallicadpa alternates deadlift/row and bench/OHP weekly; GZCLP rotates four workouts over three days; Ivysaur and GSLP run a two-week A/B rotation; 5/3/1 rotates four weeks. `program.order` is a flat index — it cannot say "A1 B1 A2 / B2 A1 B1". Propose `program.cycle` (list of file ids in order, wrapping) and `program.week` for multi-week schemes.
- **One file = one session, except 5/3/1.** As instructed, each 5/3/1 week file holds four separate training days as blocks; the timer would run them back-to-back. Needs a "day" grouping inside a file, or a `program.sessions[]` wrapper — the flat `items` list cannot express "these blocks are different days".
- **Supersets.** RR pairs and Metallicadpa's pushdown/lateral-raise supersets are one block with both exercises and one rest — fine. But the RR's "rest 90 s after *each* exercise" and its "3 min between sets of the same exercise" rule work only because both rests are listed explicitly; a `superset: true` flag with `restBetween`/`restAfter` would be cleaner.
- **Progressions (RR).** "Pull-up progression" is a ladder of 5–6 variations; the file points at the target key (`bw_pullup`) with the ladder in `note`. Propose an exercise `progression: [keys]` in the library, and let the step reference the ladder rather than a rung.
- **Warm-up sets** ("warm up to the first lift", StrongLifts' bar → ramp) are text only. A block `role: "warmup"` (excluded from volume/score) would let programs include them.
- **Rest.** StrongLifts is really 90 s / 3 min / 5 min depending on how the last set went; GZCLP's 3–5 / 2–3 / 1–1.5 min tiers; RR "up to 3 min if reps drop". Encoded as a single number with the range in the block note. Propose `restSec` + `restMaxSec`, or `asNeeded` (same ask as crossfit-girls).
- **Deadlift 1×5** is a block `repeat: 1` containing one exercise step and a trailing rest; the rest is pointless but keeps the "block = sets" convention uniform.
- **Level** is a guess: LP programs Medium, nSuns/PHUL power/Ivysaur AMRAP days Hard, 5/3/1 deload Easy. Programs scale to the user's TM so a fixed level is nearly meaningless; consider dropping `level` for `kind: program`.
- **Rest defaults where the source gives none** (Starting Strength, PHUL, nSuns, 5/3/1 main sets): 180 s on 3–5-rep barbell work, 120 s on nSuns T2, 90 s on 6–12-rep work, 60 s on isolation, noted in the block. The schema's "90 s for strength" default is too short for heavy fives.

## Exercises
- 15 new keys in `new-exercises.json`: `bb_sumo_deadlift`, `bb_close_grip_bench`, `bb_skullcrusher`, `db_chest_fly`, `machine_calf_raise`, `machine_seated_calf_raise`, `machine_calf_press`, `bw_inverted_row`, `bw_nordic_curl`, `bw_deadbug`, `bw_arch_hang`, `bw_support_hold`, `bw_reverse_hyper`, `cable_pallof_press`, `cable_band_dislocate`. `bb_power_clean` reused from crossfit-heroes.
- Machine calf work uses group `barbell` (label "Barbell & machines"); Pallof press and band dislocates use group `band` under a `cable_` prefix because there is no `band_` prefix.
- Reused with a note instead of adding keys: `db_curl` for seated incline curls, `cable_tricep_pushdown` for cable triceps extensions, `db_tricep_ext` for overhead extensions, `cable_lat_pulldown` for "pulldowns or pull-ups", `bw_chinup` for weighted chins, `bw_plank` for the anti-extension ladder.
- `bw_calf_raise` (nhs) and `gym_ring_row` (crossfit-heroes) exist; programs use loaded `machine_calf_raise` and the generic `bw_inverted_row` (bar, rings or table) instead.
