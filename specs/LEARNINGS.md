# Learnings

Append-only. One line per gotcha: `- <date> <role>: <what turned out to be true>`. Read before building; append when something non-obvious cost you time.

- 2026-09-12 Nick: the app shell is network-first and a Cloudflare rule keeps /sw.js uncached, so a stale service worker cannot strand a phone.
- 2026-09-18 Nick: the iOS project is generated by XcodeGen; the iPhone 17 Pro simulator works; UI tests export screenshots.
- 2026-09-19 runner: git pushes to GitHub stall on HTTP/2 from these machines; set http.version=HTTP/1.1 per clone.
- 2026-09-20 builder: a session's origin (startedFrom) lives only in App state, set on every path into /w/:id and cleared when a tab renders; a reload during the timer or the Resume banner loses it, so those sessions save without startedFrom rather than with a stale one.
- 2026-09-20 builder: the unattended builder session cannot run xcodebuild, xcrun or swiftc (denied, no approval surface); an iOS change goes up compiled only in the harness's own xcodebuild run, so keep Swift diffs small and mirror existing code exactly.
- 2026-09-20 builder: the unattended Builder session cannot run xcodebuild, xcodegen, simctl, swiftc or `gh pr ready` (permission denied, nobody to approve; git push and `gh pr create` work); iOS proof has to come from the harness, and a new test file goes into project.pbxproj by hand as four entries.
- 2026-09-21 builder: startedFrom sits at the top of a session row's `data` for v2 rows but under `data.v2` for rows that began in v0.9, so a reader needs both paths; the iOS SessionResult has no startedFrom, so gym sessions count under "none" and an iOS edit of a web session re-encodes without it.
- 2026-09-22 builder: the committed project.pbxproj lists every file, so a new Swift or resource file needs `xcodegen generate` in ios/ and the regenerated project committed with it; the builder sandbox has no sips or qlmanage, so icon PNGs are rendered and checked with Node scripts kept in the PR.
- 2026-09-25 builder: recommend() identifies a creator by source.author, falling back to creator; own workouts get both set to the settings name on save (App.tsx), so they count as a creator match only once that name has two sessions in history, and a workout with neither string never matches by creator.
- 2026-09-26 builder: For you is blank with history only when recommend() returns []; on main that needs a catalogue where every candidate differs in kind, creator, exercises and duration (>5 min) from what was done, under PR #18's rules it only needs no creator with two sessions and no two shared exercises, so a fixture of four creators with no exercise in common is empty under both.
- 2026-09-23 builder: the iOS workout screen already drags steps inside a block (onMove landed with the redesign, 45ef2cf); what is missing is drag between blocks, blocks by their header, and block settings on that screen. The web DnD variants are named classic, seams (A), pointer (B) and buttons (C) in runsheet-list.tsx.
- 2026-09-27 builder: `.preferredColorScheme(nil)` on a fullScreenCover that was `.dark` does not hand back the app's appearance; the finish screen stayed dark in a light app. Pass the outside colour scheme in and set it by value.
- 2026-09-27 builder: the iOS History tab has no Repeat button, so the phone's 'history' origin comes from the Pick up again carousel on the Workouts tab (built from store.results); an origin rides the NavigationStack path as DiscoverView.Opened(key:from:), and the crash-safe RunState does not carry it, so a resumed session saves without one, as the web does after a reload.
- 2026-09-27 builder: set times are session time with pauses taken out, stored on the Actual as `at` when the set is ticked; a crash-safe run saved before that falls back to doneAt less every pause. `fmtClock` rounded only the seconds, so 59.6 s read "0:60"; it rounds the whole now. The pace ghost matches rounds on block id and sets on step id, so a block rebuilt with new ids has no last time to race.
- 2026-09-27 builder: on the simulator a springboard query for a Live Activity button takes several seconds, so a Lock Screen tap test cannot catch a 10 s Tabata rest; testLockScreenControls uses Iron Base's Pull block (user-paced sets, long rests). A tap on a stale card is dropped by the token check in SessionRunner.control.
- 2026-09-28 builder: a Store test with healthOverride = true that changes a session's effort reaches Health.shared.setEffort, which takes about three minutes on the simulator; give Health calls a seam (Store.healthDelete, deviceSummary) and change another field in tests.
- 2026-09-28 builder: SwiftUI's `buttonRepeatBehavior(.enabled)` repeats at a steady ~0.5 s and never speeds up (45 → 55 kg in a 2.5 s hold), so the iOS steppers time their own repeats off the button style's `isPressed` (`RepeatButton` in Features/Toasts.swift).
- 2026-09-28 builder: on iOS 26 a `confirmationDialog` hides its `role: .cancel` button; an option that has to show ("Keep going" on the timer's X) goes in without a role.
- 2026-09-28 builder: a UI test that starts a session now meets the notification permission alert; the walkthroughs launch with `UITEST_NO_PROMPTS=1` and only testRestNotificationAsked clears it.
