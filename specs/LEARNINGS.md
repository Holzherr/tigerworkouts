# Learnings

Append-only. One line per gotcha: `- <date> <role>: <what turned out to be true>`. Read before building; append when something non-obvious cost you time.

- 2026-09-12 Nick: the app shell is network-first and a Cloudflare rule keeps /sw.js uncached, so a stale service worker cannot strand a phone.
- 2026-09-18 Nick: the iOS project is generated by XcodeGen; the iPhone 17 Pro simulator works; UI tests export screenshots.
- 2026-09-19 runner: git pushes to GitHub stall on HTTP/2 from these machines; set http.version=HTTP/1.1 per clone.
- 2026-09-20 builder: a session's origin (startedFrom) lives only in App state, set on every path into /w/:id and cleared when a tab renders; a reload during the timer or the Resume banner loses it, so those sessions save without startedFrom rather than with a stale one.
- 2026-09-20 builder: the unattended builder session cannot run xcodebuild, xcrun or swiftc (denied, no approval surface); an iOS change goes up compiled only in the harness's own xcodebuild run, so keep Swift diffs small and mirror existing code exactly.
- 2026-09-20 builder: the unattended Builder session cannot run xcodebuild, xcodegen, simctl, swiftc or `gh pr ready` (permission denied, nobody to approve; git push and `gh pr create` work); iOS proof has to come from the harness, and a new test file goes into project.pbxproj by hand as four entries.
- 2026-09-21 builder: startedFrom sits at the top of a session row's `data` for v2 rows but under `data.v2` for rows that began in v0.9, so a reader needs both paths; the iOS SessionResult has no startedFrom, so gym sessions count under "none" and an iOS edit of a web session re-encodes without it.
- 2026-09-22 builder: the committed project.pbxproj lists every file, so a new Swift or resource file needs `xcodegen generate` in ios/ and the regenerated project committed with it; the builder sandbox has no sips or qlmanage, so icon PNGs are rendered and checked with Node scripts kept in the PR.
